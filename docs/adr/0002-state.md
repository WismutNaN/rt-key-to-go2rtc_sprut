# ADR-0002: Состояние камер и last-known-good

**Дата**: 2026-09-06
**Статус**: Принято

## Контекст

Порядок камер в API нестабилен, но RTSP-ссылки SprutHub должны оставаться постоянными. После перезапуска controller также должен восстановить ещё действующий upstream без ожидания успешного запроса Ростелекома.

## Рассматриваемые варианты

1. **Не хранить состояние** — просто, но перестановка камер меняет ссылки.
2. **SQLite** — транзакции и схема, но избыточно для нескольких камер и одного процесса.
3. **Версионированный JSON** — прозрачно, достаточно при атомарной записи и резервной копии.

## Решение

Выбрали **JSON в постоянном Docker volume**. При первом обнаружении из `title` строится ASCII slug; пустой или конфликтующий title дополняется короткой частью UID. JSON хранит UID, стабильное имя, исходный title, последний проверенный upstream URL, media profile и его `exp`. Запись выполняется во временный файл, синхронизируется и атомарно заменяет основной; предыдущая валидная версия сохраняется как backup. Файл имеет права `0600`.

## Последствия

**Становится проще**: отладка, резервирование, перенос mapping.
**Становится сложнее**: файл содержит временные upstream-токены и требует защиты.
**Закрывает дверь на**: автоматическое переиспользование имён исчезнувших камер; это сделано намеренно для стабильности.
