# ADR-0007: Ленивый медиатракт и профиль совместимости SprutHub

**Дата**: 2026-09-07
**Статус**: Принято

## Контекст

Исходные потоки Ростелекома содержат H.264 и AAC-LC, но у видео наблюдаются
скачки и повторы DTS. Первый вариант принудительно назначал packet timestamps по
системному времени и программно кодировал H.264 CFR. В SprutHub один активный
720p-поток создавал высокую CPU-нагрузку, RTSP timeout и зелёные кадры. FFmpeg
отдельно предупреждает, что wallclock timestamps дают неопределённый результат
при наличии B-кадров.

## Рассматриваемые варианты

1. **Video-only copy** — минимальная нагрузка; FFmpeg перепаковывает H.264 с
   demuxer time base без media decode/encode.
2. **Постоянный FFmpeg для всех камер** — предсказуемый media stream, но высокая
   фоновая нагрузка и лишние подключения к облаку.
3. **H.264 CFR по умолчанию** — исправляет часть несовместимых источников, но даже
   один consumer может перегрузить слабый сервер; «ленивость» не помогает, если
   SprutHub удерживает RTSP-сессию постоянно.

## Решение

Выбрали **video-only H.264 copy по умолчанию**. Input template больше не
подменяет timestamps системным временем; для stream copy используется demuxer
time base. go2rtc хранит source без активного FFmpeg-процесса, а при подключении
consumer только перепаковывает H.264. H.264 CFR, scaling, уменьшение FPS и
неподтверждённое аудио удалены из поддерживаемой конфигурации.
Автоматический healthcheck использует
только RTSP `OPTIONS`; `DESCRIBE` всех upstream выполняется при смене token и по
явной команде `check-streams`. Неизменившийся source повторным PATCH не заменяется.

Snapshot использует этот же producer, декодирует только один keyframe в JPEG и
кэширует его. Snapshot polling поэтому не удерживает video encoder.

## Последствия

**Становится проще**: активная RTSP-сессия SprutHub не требует media
decode/encode; отсутствующие timestamps и time base обрабатываются без
wallclock-подмены.

**Становится сложнее**: исходное разрешение нельзя изменить внутри шлюза;
аудио пока недоступно в публичном профиле.

**Закрывает дверь на**: постоянную фоновую аналитику внутри этого проекта. Для
Frigate или архива отдельный постоянный consumer должен подключаться осознанно.
