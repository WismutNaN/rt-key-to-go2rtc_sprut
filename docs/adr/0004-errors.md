# ADR-0004: Обработка ошибок и деградация

**Дата**: 2026-09-06
**Статус**: Принято

## Контекст

API и streamer-токены неофициальны, Bearer Token может перестать работать, а частичный сбой не должен выключать остальные камеры. Нельзя заменять рабочее состояние неподтверждёнными данными.

## Рассматриваемые варианты

1. **Fail-fast всего процесса** — хорошо заметно, но одна камера останавливает все.
2. **Игнорировать ошибки** — поток может продолжиться, но оператор не увидит деградацию.
3. **Частичный успех + last-known-good + unhealthy** — сохраняет работающие камеры и сообщает о проблеме.

## Решение

Выбрали **частичное обновление по камерам**. Ошибки классифицируются на auth, transport, schema, validation и go2rtc. Controller logs содержат adapter/UID и класс ошибки, но скрывают Bearer, streamer-токены, пароли и полный source. Сторонние media-логи go2rtc/FFmpeg отделены и считаются чувствительными. Новый source становится last-known-good только после успешного PATCH, проверки имени и RTSP/upstream probe. При отказе probe восстанавливаются прежние upstream и media profile.

## Последствия

**Становится проще**: локализация отказа и восстановление.
**Становится сложнее**: health может быть degraded при работающей части камер.
**Закрывает дверь на**: молчаливую замену last-known-good пустым или неполным ответом API.
