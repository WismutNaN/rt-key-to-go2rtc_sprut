# ADR-0001: Стек и границы сервисов

**Дата**: 2026-09-06
**Статус**: Принято

## Контекст

Существующий Python-скрипт нужно превратить в переносимый сервис, а go2rtc обновлять без restart. Целевая машина — Linux-сервер в локальной сети с Docker Compose; машина разработки Docker не имеет.

## Рассматриваемые варианты

1. **Один контейнер с двумя процессами** — API можно оставить на loopback, но нужен supervisor и смешиваются жизненные циклы.
2. **Два контейнера** — ясное разделение, стандартный restart и тестируемый контроллер; API доступен во внутренней сети.
3. **Оставить systemd/cron** — меньше миграции, но сохраняются restart и зависимость от окружения хоста.

## Решение

Выбрали **Docker Compose из `controller` на Python 3.12 и `go2rtc` 1.9.14**, потому что компоненты связаны простым HTTP-контрактом и могут перезапускаться независимо. Base controller закреплён на `python:3.12.14-alpine3.24`, go2rtc — на multi-arch image `alexxit/go2rtc:1.9.14`; плавающие `latest` не используются. Host networking не используется: WebRTC отключён, а целевой RTSP output go2rtc работает через RTP interleaved/TCP на одном опубликованном порту.

## Последствия

**Становится проще**: перенос, обновление source, изоляция зависимостей, поддержка `amd64/arm64`.
**Становится сложнее**: API нельзя буквально привязать к `127.0.0.1`; нужна внутренняя сеть и Basic Auth.
**Закрывает дверь на**: управление только через cron и безусловный restart всего go2rtc.
