# ADR-0005: Изоляция API go2rtc

**Дата**: 2026-09-06
**Статус**: Принято

## Контекст

Controller должен вызывать `PATCH /api/streams`, поэтому API go2rtc нельзя полностью отключить. В двух контейнерах привязка API к `127.0.0.1` сделает его недоступным controller, а публикация `1984` в LAN раскрывает чувствительное управление и конфигурацию.

## Рассматриваемые варианты

1. **Опубликовать `1984` с паролем** — удобно отлаживать, но поверхность атаки остаётся в LAN.
2. **Один container network namespace** — позволяет loopback, но связывает развёртывание контейнеров.
3. **Обычная внутренняя Compose-сеть без host port** — controller доступен API, устройства LAN нет.

## Решение

Выбрали **API на интерфейсе контейнера, но без секции `ports` для `1984`**,
дополнительно с Basic Auth, `local_auth: true` и allowlist путей `/api/streams`
и `/api/frame.jpeg`. Наружу публикуются RTSP `8554/tcp` и отдельный узкий
snapshot endpoint `8080/tcp` с credentials SprutHub; произвольные методы API и
Web UI через него недоступны.

## Последствия

**Становится проще**: controller общается по имени сервиса, API отсутствует в LAN.
**Становится сложнее**: Web UI доступен только через временный диагностический tunnel/exec, который не входит в v1.
**Закрывает дверь на**: прямое открытие `http://server:1984` из домашней сети.
